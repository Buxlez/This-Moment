# 网易云候选校验可靠性修复设计

**日期：** 2026-08-04  
**状态：** 待书面确认  
**范围：** 网易云登录识别、请求限流、候选扩展与真实可播放校验

## 1. 目标与成功标准

修复“模型已生成候选，但音乐卡片显示 0 首”的问题，同时保留“只有取得真实播放地址的歌曲才进入卡片”这一原则。

完成后应满足：

- 本地 Cookie 在 `/login/status` 缺少 profile 时，可通过 `/user/account` 正确识别登录账号；
- 网易云候选查询不再以突发并发方式连续请求；
- `405` 或 `429` 限流响应会自动退避重试，不会立即丢弃候选；
- 默认从 32 首候选中逐步校验，找到 8 首后立即停止后续查询；
- 普通账号与 VIP/SVIP 使用同一逻辑，会员只影响网易云返回的实际播放权限；
- 仍无法取得播放地址时如实显示实际数量，不加入不可播放占位歌曲；
- 一轮推荐的目标完成时间为 15–45 秒。

## 2. 登录状态

`verifyLoginStatus` 依次检查：

1. `/login/status` 的 `data.profile.userId` 或 `profile.userId`；
2. 若 profile 缺失，再请求 `/user/account`，读取 `account.id`；
3. 两个接口都无法识别账号时才返回未登录。

当前 Cookie 已经能通过 `/user/account` 返回账号 ID，因此修复后 UI 状态应显示已登录。不会输出或记录完整 Cookie。

## 3. 请求调度与限流恢复

网易云候选校验使用单进程共享的请求节流器：

- 相邻网易云请求至少间隔 350 ms；
- 只对明确的 `405`、`429` 限流响应重试；
- 最多重试 2 次，退避等待分别为约 700 ms、1400 ms；
- 其他 HTTP 错误、无播放 URL 和匹配失败不重试；
- 播放器的即时 URL 解析复用同一节流器，避免生成过程中再次形成突发请求。

错误对象保留 HTTP 状态码，日志仅记录状态和脱敏消息。

## 4. 候选池与提前停止

DeepSeek 默认生成 `8 × 4 = 32` 首候选。校验并发从 4 降为 2，并按候选顺序保存结果。

每个候选依次经过：

1. 网易云搜索；
2. 标题与歌手严格匹配；
3. 当前账号真实播放 URL 校验；
4. 仅对可播放歌曲查询封面、专辑与时长；
5. 去重并加入结果。

一旦累计 8 首，两个工作线程停止领取新候选。若 32 首处理完仍不足 8 首，卡片显示实际数量和现有诚实降级提示。

## 5. 缓存

使用进程内短期缓存减少同一会话的重复请求：

- 搜索结果：10 分钟；
- 可播放判断：2 分钟；
- 歌曲详情：30 分钟。

缓存只保存歌曲元数据和短期可播判断，不保存新的用户隐私数据。播放器仍会在真正播放时重新解析短效 URL。

## 6. 测试与真实验收

测试先行覆盖：

- `/login/status` 无 profile、`/user/account` 有账号时判定登录成功；
- `405` 第一次失败后退避重试并成功；
- 非限流错误不重试；
- 请求节流保持最小间隔；
- 校验达到 8 首后不会继续搜索剩余候选；
- 缓存命中不重复调用网易云；
- 原有匹配、去重、封面和播放队列测试保持通过。

真实验收使用当前 SVIP 账号重新启动服务并生成一轮推荐，检查：登录状态、日志中是否仍有未恢复的 `405`、卡片歌曲数量、封面加载及至少一首歌曲实际播放。

## 7. 非目标

- 不展示无法播放的歌曲来填满数量；
- 不绕过会员、版权或地区限制；
- 不引入第二个音乐平台；
- 不改变当前卡片式 UI 结构；
- 本轮不处理火山引擎 TTS 配置。
