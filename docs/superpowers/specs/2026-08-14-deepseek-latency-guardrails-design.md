# DeepSeek 延迟护栏设计

## 目标

缩短结构化音乐推荐的模型调用时间，并确保单次请求不会无边界等待。此次试验只调整 DeepSeek 调用参数与重试边界，不修改音乐筛选、卡片界面、TTS 或播放逻辑。

## 调用参数

- 模型保持 `deepseek-v4-flash`。
- 显式设置 `thinking: { type: 'disabled' }`，避免简单 JSON 生成默认进入思考模式。
- 保持 `response_format: { type: 'json_object' }` 与非流式输出。
- 设置 `max_tokens: 4000`。该值只限制模型输出，为 16 首候选的 JSON 留出充足空间，同时防止异常输出无限增长。
- OpenAI 兼容客户端设置单次请求超时 45 秒。
- 关闭 SDK 内置自动重试，避免一次业务调用隐式扩展为三次网络请求。

## 重试边界

- 正常情况下只调用模型一次。
- 仅当 API 已成功返回、但内容为空、JSON 无法解析或结果不符合推荐 Schema 时，允许再调用一次修复输出。
- 网络错误、超时、鉴权、余额、限流与服务端错误不在业务循环内自动重试，由现有公开失败路径处理。
- 因此单次正常请求上限约 45 秒；仅结构化输出失败时，最坏情况允许第二次 45 秒请求。

## 提示词与输出

- 保留当前 system 指令中的 `JSON` 字样。
- 保留用户提示中的 JSON 字段示例，符合 DeepSeek JSON Output 要求。
- 不记录提示词、API Key、用户原文或模型原始输出。

## 测试与验收

- 测试证明客户端收到 `timeout: 45000` 与 `maxRetries: 0`。
- 测试证明请求包含关闭思考、4000 token 上限、JSON Output 和非流式参数。
- 测试证明网络或超时错误只调用一次。
- 测试证明无效 JSON 或 Schema 可触发且最多触发一次修复调用。
- 全量测试通过后重启本地服务。
- 用同一类普通音乐需求进行至少三次真实测试，记录卡片创建耗时与成功率；不输出任何凭据或播放 URL。

## 非目标

- 不更换模型。
- 不启用流式 JSON。
- 不改变 16 首模型候选与最多 8 首最终歌曲的设计。
- 不调整网易云请求并发与缓存。
- 不缩短或延长前端 111 秒轮询预算；先依据本轮真实数据决定是否调整。
