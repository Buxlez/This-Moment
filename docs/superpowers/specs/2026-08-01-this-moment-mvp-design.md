## 1. 设计结论

本 MVP 直接以 Claudio-FM 的完整本地技术路径为基础，不另建“氛围、能量、节奏”语义转译中间层。系统把用户输入、`taste.md`、`mood-rules.md`、当前时间、用户选择的天气、最近播放和最近对话拼成 Prompt，由 DeepSeek 直接生成推荐语和候选歌曲，再通过网易云搜索、播放校验和去重，返回最多 20 首可以点击播放的歌曲。

核心链路：

```text
用户说一句话
+ taste.md
+ mood-rules.md
+ 系统当前时间
+ 用户选择的天气
+ 最近播放和对话
        ↓
Claudio-FM 式 Context Prompt
        ↓
DeepSeek 直接生成推荐语和约 30 首候选歌曲
        ↓
网易云搜索、匹配、去重和播放校验
        ↓
最多 20 首音乐卡片
        ↓
轻量推荐语 TTS + 点击播放
```

## 2. MVP 要验证的事情

1. 用户说一句模糊的话，系统能够给出符合当下感觉的歌曲。
2. 用户选择不同天气后，相同或相似表达会得到不同倾向的推荐。
3. 推荐结果来自真实网易云搜索结果，并且可以点击播放。
4. `taste.md` 和 `mood-rules.md` 可以明显影响推荐结果。
5. 用户说“再安静一点”或“换一批”时，系统能参考最近对话继续推荐。
6. 每张卡片的两句推荐语可以通过 TTS 播放。

## 3. MVP 不做什么

- 不实现完整 PRD 的字段级来源追踪；
- 不单独输出氛围、能量和节奏；
- 不接真实天气 API；
- 不接真实车机环境；
- 不同时接入网易云、QQ 音乐和酷狗；
- 不自动学习长期用户偏好；
- 不导入网易云红心和完整收听历史；
- 不实现 AI DJ、歌曲间串场、来电模拟和逐首介绍；
- 不实现定时节目和无限自动续播；
- 不进行第二轮大模型补选；
- 不引入 Redis、PostgreSQL、独立 Worker 或向量数据库；
- 不作为公共服务或商业产品部署。

## 5. 用户完整流程

1. 用户运行 `yarn start`。
2. 启动脚本检查本地网易云 sidecar。
3. 未登录时，页面提供网易云二维码登录入口；登录 Cookie 仅保存在本地。
4. 用户打开 `http://localhost:8080`。
5. 页面默认选择“晴朗”，时间读取电脑当前时间。
6. 用户可以切换天气预设。
7. 用户输入“上班路上有点困，想提神但别太吵”。
8. 页面显示“正在理解 → 正在找歌 → 正在确认播放 → 正在整理卡片”。
9. DeepSeek 生成两句推荐语和约 30 首候选歌曲。
10. 系统在网易云搜索候选，过滤错配、重复、近期歌曲和不可播放歌曲。
11. 页面返回最多 20 首音乐卡片，并在后台合成推荐语 TTS。
12. 用户可点击“播放推荐语”、单曲播放或“播放全部”。
13. “播放全部”默认先播推荐语，再从卡片第 1 首开始顺序播放。
14. 用户继续输入“再安静一点”或“换一批”。
15. 系统把最近对话、最近播放和上一张卡片歌曲加入 Prompt，生成下一张卡片。
16. 旧卡片保留在页面和 SQLite 中，可再次播放。

## 6. 天气模拟

MVP 不请求真实天气。页面提供六个单选预设：

| 预设 | 提供给模型的描述 |
|---|---|
| 晴朗 | 天气晴朗，整体明亮、轻松 |
| 多云 | 多云，整体柔和、平稳 |
| 小雨 | 小雨，环境松弛、有空间感 |
| 大雨 | 大雨，环境包裹感强、外界噪声较明显 |
| 炎热 | 天气炎热，希望听感清爽、轻盈 |
| 寒冷 | 天气寒冷，希望听感温暖、舒展 |

默认选择“晴朗”。天气只作为软提示加入上下文，不直接映射固定歌曲。用户原话优先：即使页面选择“晴朗”，用户说“外面正在下雨”，模型仍应按用户明确表达理解。

时间始终读取电脑当前时间。MVP 不提供时间编辑器和城市选择器；如果用户在原话中说出城市或时间，模型可以按自然语言理解。

## 7. 技术架构

```text
Claudio-FM Static PWA
  ├─ 天气预设
  ├─ 自然语言输入
  ├─ 生成进度
  ├─ 音乐卡片历史
  └─ HTMLAudioElement 播放器
             │ HTTP + WebSocket
             ▼
Claudio-FM Node Local Server
  ├─ router.js
  ├─ context.js
  ├─ llm.js
  ├─ music.js / music-netease.js
  ├─ tts.js
  ├─ state.js
  └─ server.js
             │
             ├─ DeepSeek API
             ├─ Volcengine TTS API
             ├─ NeteaseCloudMusicApi sidecar
             └─ SQLite
```

继续使用原生 HTML、CSS 和 JavaScript，不增加 React、TypeScript、Vite 或独立前端服务。前端静态文件继续由 Express 提供，WebSocket 继续负责生成进度和播放状态推送。

## 9. 模糊诉求如何变成歌曲

### 9.1 上下文组装

`context.js` 沿用 Claudio-FM 的拼装顺序：

```text
音乐推荐角色说明
+ user/taste.md
+ user/routines.md
+ user/mood-rules.md
+ 系统当前时间
+ 用户选择的天气
+ 最近 20 首播放记录
+ 最近 8 条对话
+ 上一张卡片的歌曲
+ 用户本轮输入
+ JSON 输出约束
```

不在代码里写复杂的场景分类器。用户说“困”“累”“想放松”或“别太吵”时，主要由 `mood-rules.md` 提供提示，大模型结合完整语境直接选歌。

### 9.2 模型输出

模型只返回：

```json
{
  "title": "清醒一点，慢慢出发",
  "say": "上海的早晨很亮，想提神又不想太吵，就让节奏稳稳往前走。接下来这些歌有推动感，但不会一下把声音推得太满。",
  "play": [
    "歌曲名 - 歌手名"
  ],
  "reason": "仅写入日志的内部简短说明"
}
```

`play` 目标为 30 首候选。推荐语 `say` 必须为两句话、45–70 个中文字符，不暴露算法、Prompt 或内部推理。

模型输出无法解析时重试一次相同请求并强调 JSON 格式；第二次仍失败则本轮失败，不从普通文本中猜测歌曲。

### 9.3 连续调整

连续调整不建立独立字段继承系统，而是沿用 Claudio-FM 的最近消息和最近播放上下文：

```text
上一轮：上班路上有点困，提神但别太吵
本轮：再安静一点
```

模型从最近对话理解“再安静一点”针对上一张卡片，并从新候选中避开上一张卡片和近期歌曲。“换一批”同样依赖最近上下文保持大致方向。

## 10. 网易云校验和 20 首卡片

模型给出的约 30 首歌曲只是候选。系统按候选顺序执行：

1. 使用“歌名 + 歌手”搜索网易云；
2. 核对返回歌名和歌手，过滤明显错配；
3. 获取平台歌曲 ID 和元数据；
4. 调用播放地址接口确认当前可播放；
5. 过滤同一卡片重复歌曲；
6. 过滤最近 24 小时已进入队列的歌曲；
7. 限制最近连续出现同一歌手；
8. 收集前 20 首合格歌曲。

搜索并发上限为 4，避免 sidecar 瞬时请求过多。MVP 不执行第二轮模型补选；如果最后只有 13 首，就返回 13 首并显示“部分候选在当前音源不可播放”。不得使用 `yt-dlp` 或其他平台补足。

卡片固定保存本轮歌曲顺序，旧卡片不会因为后续请求而变化。

## 11. 推荐语 TTS

继续使用 Claudio-FM 的 `tts.js` 和火山引擎豆包语音，但只合成卡片的 `say`：

1. 卡片保存成功后开始合成；
2. 以“文本 + 音色 + 语速”的哈希作为 MP3 缓存文件名；
3. WebSocket 推送 `tts-ready` 或 `tts-failed`；
4. 卡片提供“播放推荐语”按钮；
5. “播放全部时先播推荐语”默认开启；
6. 用户点击“播放全部”后先播放推荐语，再播放第 1 首；
7. 用户直接点击单曲时立即播放歌曲，不插入推荐语。

卡片生成后只预生成语音，不自动播放。TTS 未配置、合成失败或播放失败都不影响文字、歌曲卡片和音乐播放。

## 12. 页面结构

页面由六部分组成：

1. `this moment` 标题和网易云登录状态；
2. 六个天气预设按钮；
3. 自然语言输入框和发送按钮；
4. 生成进度提示；
5. 按时间倒序排列的音乐卡片；
6. 固定底部播放器。

每张卡片显示：

- 标题；
- 两句推荐语；
- 本轮天气；
- 网易云来源；
- 实际歌曲数量；
- “播放推荐语”“播放全部”“换一批”；
- 前 6 首歌曲和“展开全部”；
- TTS 或歌曲不足警告。

播放器支持单曲播放、播放全部、暂停、继续、上一首、下一首、进度拖动和自动播放队列下一首。

## 13. API 与实时事件

### HTTP

- `POST /api/chat`：沿用入口，增加 `weather`；
- `GET /api/cards`：返回当前会话历史卡片；
- `GET /api/cards/:id`：返回一张固定卡片；
- `GET /api/weather-presets`：返回六个天气预设；
- `POST /api/playback/resolve`：按网易云歌曲 ID 刷新播放地址；
- `POST /api/cards/:id/tts/retry`：重新合成推荐语；
- `GET /api/tts/:filename`：安全返回本地 TTS MP3；
- `GET /api/now`：保留当前播放状态；
- `GET /api/next`：保留下一首控制。

`POST /api/chat` 请求：

```json
{
  "message": "上班路上有点困，想提神但别太吵",
  "weather": "sunny"
}
```

### WebSocket `/stream`

- `recommendation-status`：理解、找歌、校验、整理阶段；
- `recommendation-ready`：完整音乐卡片；
- `tts-ready`：推荐语 MP3 已就绪；
- `tts-failed`：TTS 失败但卡片可用；
- `control`：播放、暂停、上一首和下一首。

## 14. SQLite 数据

保留 Claudio-FM 原表：

- `plays`：最近进入播放队列的歌曲；
- `messages`：最近用户输入和推荐语；
- `prefs`：天气选择和播放器开关。

新增：

- `cards`：标题、推荐语、天气、歌曲数量、TTS 状态、TTS 文件、警告和创建时间；
- `card_tracks`：卡片 ID、固定顺序、网易云歌曲 ID、歌名、歌手、专辑、封面和时长。

首版不根据这些记录自动修改 `taste.md` 或 `mood-rules.md`。

## 15. 异常和降级

| 异常 | MVP 行为 |
|---|---|
| DeepSeek 未配置 | 页面显示配置说明，不生成假结果 |
| 模型请求失败 | 显示重试入口 |
| JSON 连续两次无法解析 | 本轮失败，不猜测结果 |
| 网易云 sidecar 未启动 | 启动脚本提示并阻止推荐 |
| 网易云未登录 | 显示二维码登录入口 |
| 少于 20 首可播放歌曲 | 返回实际数量并显示提示 |
| 单曲播放地址过期 | 点击播放时刷新一次，失败则跳过 |
| TTS 失败 | 保留文字、卡片和音乐播放 |
| WebSocket 中断 | 重新连接后通过卡片接口恢复结果 |
| SQLite 保存失败 | 不返回未保存的成功卡片 |

## 16. 本地安全要求

- `.env`、网易云 Cookie、SQLite、TTS 缓存和运行日志不得提交；
- 日志不得打印完整 API Key、Cookie 或播放 URL；
- 用户输入最多 500 个字符；
- 播放 URL 不长期保存，播放时重新解析；
- TTS 文件名使用哈希，文件接口只能读取 `cache/tts/` 下的 MP3；
- README 明确注明 Claudio-FM 来源、锁定基线和本地原型限制。

## 17. 测试范围

### 单元测试

- 天气预设选择和默认晴朗；
- `context.js` 包含时间、天气、taste、规则、历史和本轮输入；
- 用户原话中的天气能够覆盖页面天气提示；
- 模型 JSON 解析与一次重试；
- 歌名/歌手匹配、重复过滤和近期过滤；
- 卡片歌曲顺序；
- TTS 缓存键；
- 播放队列上一首、下一首和自动续播。

### 集成测试

- 假模型返回 30 首，假音源成功保留 20 首；
- 只有 13 首可播放时如实返回 13 首；
- “再安静一点”能够带上最近对话和上一张卡片；
- TTS 成功和缓存命中；
- TTS 失败不影响卡片；
- 服务重启后恢复历史卡片。

### 浏览器流程

1. 选择晴朗并请求提神但不吵；
2. 播放推荐语和整张卡片；
3. 输入“再安静一点”；
4. 切换小雨并输入“坐车回家有点累”；
5. 点击“换一批”；
6. 重启服务并确认卡片仍存在。
