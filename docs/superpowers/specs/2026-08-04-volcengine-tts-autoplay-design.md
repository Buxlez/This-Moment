# This Moment — 火山引擎推荐语 TTS 自动播放设计

**日期：**2026-08-04

**状态：**已由用户口头确认，待文档审阅

**目标：**为音乐推荐卡片生成温柔自然的女声推荐语，TTS 就绪后自动播放一次，不自动播放歌曲。

## 1. 范围

本轮只增强已有的推荐语 TTS 链路：

- 使用火山引擎旧版控制台双头鉴权调用单向流式语音合成 HTTP 接口。
- 只合成推荐卡片中的两句推荐语，不朗读用户输入、歌单标题或歌曲名。
- 语音就绪后自动播放一次，播放结束后停止。
- 歌曲始终由用户手动点击播放。
- 保留独立的“播放推荐语”能力，便于重听或在自动播放被浏览器拦截后手动启动。

本轮不做声音复刻、多角色对话、背景音效、字幕时间轴、公网音频存储或歌单自动播放。

## 2. 官方接口与鉴权

使用官方的[单向流式语音合成 HTTP](https://docs.volcengine.com/docs/6561/2528925?lang=zh)：

```text
POST https://openspeech.bytedance.com/api/v3/tts/unidirectional
```

旧版控制台鉴权按[旧版控制台鉴权参考示例](https://www.volcengine.com/docs/6561/2534847?lang=zh)执行：

| 本地配置 | HTTP 请求头 | 说明 |
| --- | --- | --- |
| `VOLCENGINE_TTS_APP_ID` | `X-Api-App-Id` | 旧版控制台 APP ID |
| `VOLCENGINE_TTS_ACCESS_TOKEN` | `X-Api-Access-Key` | 旧版控制台 Access Token |
| `VOLCENGINE_TTS_RESOURCE_ID` | `X-Api-Resource-Id` | 固定使用 `seed-tts-2.0` |
| 每次随机 UUID | `X-Api-Request-Id` | 请求追踪标识 |

Secret Key 不是该语音合成请求的鉴权字段，不写入项目配置，不发送给语音合成接口。所有真实凭据只保存在本机 `.env`，且 `.env` 必须继续被 Git 忽略。

项目同时保留新版 `X-Api-Key` 单头鉴权的兼容能力，但本轮真实验证使用旧版双头鉴权。鉴权选择规则为：配置 `VOLCENGINE_TTS_API_KEY` 时使用新版；否则在 APP ID 和 Access Token 同时存在时使用旧版。

## 3. 音色与音频参数

- 使用火山引擎语音合成大模型 2.0 的官方中文女声。
- 目标听感是温柔、自然、简洁，不使用夸张播音腔。
- 音色 ID 由 `VOLCENGINE_TTS_VOICE_TYPE` 配置，首次真实调用使用官方接口示例中的 `zh_female_vv_uranus_bigtts`。如账号未开通该音色，不自动猜测其他音色；实施时从账号音色库选择可用的官方女声后再重试。
- 输出格式为 MP3，采样率为 24 kHz。
- 本轮不额外改写推荐文案；TTS 直接消费已校验的卡片推荐语。

## 4. 服务端数据流

1. 用户提交音乐需求。
2. 推荐管线生成并持久化音乐卡片，将卡片立即发送给前端，不等待 TTS。
3. 后台调用 TTS Adapter，使用双头鉴权发起流式合成。
4. Adapter 逐条解析返回的 JSON 音频分片，将 Base64 数据按顺序合并为 MP3。
5. MP3 使用“提供方 + 音色 + 角色 + 文本”的稳定哈希命名，写入被 Git 忽略的 `cache/tts/`。
6. 卡片 TTS 状态从 `pending` 更新为 `ready`，并通过 WebSocket 发送 `tts-ready`。
7. 前端对当前最新卡片尝试自动播放一次。

已有非空缓存文件时直接复用，不再请求火山引擎。并发请求同一缓存键时应合并为一次上游合成，避免重复计费和文件写入竞争。

## 5. 前端交互与播放规则

卡片 TTS 状态可以是：

- `pending`：正在生成推荐语音。
- `ready`：音频可用，可自动或手动播放。
- `playing`：正在播放推荐语。
- `blocked`：浏览器拦截自动播放，等待用户点击。
- `failed`：合成失败，卡片和音乐仍然可用。

自动播放规则：

1. 只对当前会话中最新生成的卡片尝试自动播放。
2. 每张卡片最多自动播放一次；手动重听不受此限制。
3. 如果用户已手动播放歌曲，迟到的 TTS 不中断、不抢占当前音频，只将卡片更新为可手动播放。
4. 推荐语播放结束后停止，不构建歌曲队列，不自动播放第一首。
5. 浏览器拒绝 `play()` 时将状态转为 `blocked`，显示“点击播放推荐语”，不循环重试。
6. 推荐语播放或合成失败不得触发歌曲播放。

界面移除“播放全部”与“播放全部时先读推荐语”开关，保留独立的“播放推荐语”按钮和逐首歌曲播放按钮。

## 6. 错误处理与安全

- TTS 任何错误都不阻塞卡片返回、歌曲查询和手动播放。
- 对用户的错误固定为简短文案，如“推荐语音暂不可用”；不返回上游原始响应。
- 诊断日志可记录 HTTP 状态、火山引擎错误码和脱敏消息，不记录请求头、凭据、完整请求体或音频 Base64。
- 服务器状态接口只返回 TTS 是否已配置，不返回鉴权类型或任何凭据片段。
- 只从固定的火山引擎 HTTPS 终点发送凭据。
- 缓存文件名必须是合法哈希加 `.mp3`，文件只能从 `cache/tts/` 对外读取。

## 7. 测试与验收

自动化测试覆盖：

- 旧版双头鉴权请求头正确，Secret Key 不出现在请求中。
- 新版 API Key 和旧版双头鉴权的选择规则。
- 缺少成对凭据时明确失败，不发起半鉴权请求。
- 流式 JSON 分片跨 chunk 解析、Base64 合并和完整 MP3 写入。
- 非空缓存命中、并发请求合并与失败后可重试。
- TTS 成功、失败和手动重试均不影响卡片与歌曲。
- 最新卡片自动播放一次，旧卡片迟到事件不自动播放。
- 用户正在播放歌曲时 TTS 不抢占。
- TTS 结束后不自动播放任何歌曲。
- 浏览器拒绝自动播放时切换为手动播放提示。

真实验收步骤：

1. 启动实时服务，确认状态页只显示 TTS 已配置。
2. 生成一张新音乐卡片，确认卡片先出现，推荐语后台合成。
3. 确认温柔自然的女声自动播放两句推荐语。
4. 确认播放结束后页面不自动播放歌曲。
5. 手动点击任意歌曲，确认歌曲正常播放。
6. 再次播放推荐语，确认使用本地缓存，不重复请求上游。
7. 模拟 TTS 失败和浏览器自动播放拒绝，确认音乐卡片与手动歌曲播放仍然正常。

## 8. 需修改的边界

| 组件 | 职责 |
| --- | --- |
| `tts.js` | 双鉴权兼容、安全错误、缓存与并发合并 |
| `server.js` | TTS 配置判断与安全的重试接口 |
| `src/recommendation/pipeline.js` | 保持卡片先返回，后台更新 TTS 状态 |

| `test/` | Adapter、服务端、播放器与前端行为回归测试 |

## 9. 完成标准

- 真实旧版凭据可成功生成可播放的 MP3。
- 推荐语在 TTS 就绪后尝试自动播放一次。
- 推荐语播放结束后不自动播放歌曲。
- 所有歌曲仍可由用户手动点击播放。
- TTS 不抢占已经由用户启动的歌曲。
- 自动播放被拦截时存在清晰的手动入口。
- TTS 失败不影响卡片和音乐。
- 真实凭据不出现在 Git、前端资源、HTTP 响应或日志中。
- 所有新增和现有自动化测试通过，并完成一次真实浏览器验收。
